## 1. Challenges & solutions

### LLM

| # | Challenge | Cause | Solution | Result | Status |
|---|---|---|---|---|---|
| 1 | Answers took **~14 s** and sometimes came back **empty** | `sarvam-105b` reasons by default; even on "low" it spent the whole `max_tokens` budget thinking (`finish_reason: length`) | Disable reasoning (`reasoning_effort: null`). Grounded Q&A over a transcript doesn't need it. The SDK types don't allow `null`, so it's cast. | **14 s → 0.5–0.9 s**, no empty answers | ✅ |
| 2 | Answers said "the transcript" and wrote "at 0:21" instead of `[0:21]` | Prompt didn't forbid it | Prompt rules: always use `[m:ss]` citations, and say "the video" | Fixed in English; still slips in Hindi/Telugu answers | 🟡 |
| 3 | Outside facts slipping in (e.g. "the stroma is the **fluid-filled space**…", which isn't in the video) | The model "knows" the answer; a general "only use the transcript" rule isn't specific enough | Stricter rule: no facts, definitions, examples or analogies the video doesn't give, *even well-known ones*; if the video uses a term without explaining it, say so. Every factual sentence must carry a citation. | Scenario test: "Where does the Calvin cycle happen?" → "in the stroma [1:37]", no outside definition | ✅ (keep watching) |
| 4 | Citations bunched at the end or pointing to the wrong moment (e.g. `[7:04] [6:07] [8:06]`) | Model picks timestamps loosely | Rule: cite per sentence, nearest line. **Citation check** on every answer: snap each timestamp to the nearest transcript line, drop ones more than 15 s from any line, drop duplicates within a sentence | Invalid or made-up timestamps never reach the UI | ✅ |

## 2. Trade-offs

| Decision | Chose | Gave up | Why |
|---|---|---|---|
| Full transcript in the prompt vs. RAG | **Full transcript up to ~45–60 min; RAG above** (planned) | Lower cost per question on long videos | Simpler, more accurate, and handles "summarise the video" questions. **Measured** time to the LLM's first word by video length (~2.8K tokens per 9 min): 9 min **0.4 s** · 1 h **0.9–1.3 s** · 2 h **1.9 s** · 4 h **4.3 s** · ~7 h **fails** (exceeds 128K context). For voice, past ~1 h it feels slow; typed chat tolerates ~2–3 h. |
| LLM reasoning | **Off** | Possibly better answers on complex questions | 14 s → <1 s; answering from a given transcript doesn't need reasoning |
| YouTube captions vs. Sarvam STT | **Sarvam v4** for the text, **captions for timing** | Captions are free and instant | For Hinglish/Indic videos Sarvam is far more accurate (English terms, names); caption timing is still used to sharpen timestamps |
| `saaras:v3` vs. `v4` | **v4** | v3 is the documented default | v4 was complete, faster (20 s vs. 25 s) and supports key terms; v3 dropped 2 minutes |
| Estimated sentence timestamps | **Estimate + snap to captions** | Exact per-sentence timing | Batch STT has no word-level timestamps; estimates are good to within a few seconds, which is fine for "jump to this part" |
| Push-to-talk vs. hands-free call | **Call mode** | Predictability (no false triggers, no echo issues) | More natural and faster; hold-to-talk kept as a planned fallback for noisy rooms |
| What triggers barge-in | **First recognised words** | ~300 ms of reaction time vs. raw voice detection | Coughs and noise don't interrupt the tutor |
| Barge-in behaviour | **Pause instantly on the student's voice → decide from 3 words → drop the answer + filler, or resume** | A ~1 s pause when someone else talks | Talking over the tutor through speakers garbled STT; stopping outright killed answers for background talk; ducking sounded unnatural; a clean pause is what a person does, and it resumes exactly where it stopped |
| "Is this for the tutor?" check | **Separate small turn-analyzer call** (was: `<silent>` inside the main answer) | One extra ~200 ms call per utterance | The main prompt's rule got buried as context grew and couldn't be tested alone. The analyzer never sees the transcript, so it stays fast for long videos, and it has its own eval set (20/21). It also gives end-of-turn and "stop" detection for free. |
| End-of-turn wait | **Semantic** (analyzer: complete → 100 ms, unfinished → up to 2 s); punctuation as fallback | ~200 ms analyzer time on every turn | Understands meaning, not just punctuation; still ~1.2 s voice-to-voice |
| Answer length | **2–4 spoken sentences** | Depth in one go | Long answers take longer to hear and get interrupted more; follow-ups can ask for more |
| TTS per sentence | **Flush each sentence immediately** | Slightly more natural flow over longer passages | First audio arrives ~0.7 s after the question ends |
| Keeping a TTS socket open in advance | **Yes** | An idle connection per call | Saves ~150 ms on every answer |
| Audio format for calls | **Raw 16-bit PCM** | More bandwidth than MP3/Opus | No decoding delay, easy to play gaplessly and to pause/resume in the browser |
| Storage | **In memory** (transcripts, call logs, history) | Persistence across restarts | Enough for a demo; swap for SQLite/Redis later |
| Conversation memory | **Last 6 exchanges, no summary** | Memory of long sessions | Sessions on one video are short; rolling summary only if needed |
| Deployment | **Local** (repo + demo video) | A live link | YouTube blocks cloud IPs for captions/audio |
| Opening greeting | **Fixed text** in the video's language (English or Hindi), spoken via TTS | A personalised, LLM-written greeting | Instant and free (no LLM call); it's a normal turn, so the student can talk over it |
| Always run STT, even when captions exist | **Yes** (default `auto`); `captions` option available | ~17 s and some credits per video | Captions are poor for Hinglish/Indic speech; STT text + caption timing gives the best transcript. `source: "captions"` skips STT when speed matters |
| Video length limit | **60 min** | Longer lectures | Sarvam batch handles ~1 h per file without splitting; splitting needs ffmpeg (not installed). Easy to raise later |
| Key terms for STT | **Channel name + video tags** | Hand-picked terms | Automatic and usually on-topic; some tags are generic ("BTech students") but harmless |
